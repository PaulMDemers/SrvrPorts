# Staged SrvrOS WTF signal port (unbuilt review candidate)

This proposal applies to WPE WebKit 2.54.2 after the existing SrvrOS patches. It does not enable public INFO delivery or claim an accepted JSC signal port.

* `PlatformRegisters.h` needs an SrvrOS-only representation containing the complete `signal_context_snapshot`, and a separately readable interrupted stack pointer. The INFO handler copies `uc_mcontext.__srvros_snapshot` from the delivered native context while it remains live. `MachineContext.h` must read its actual RSP, RBP and RIP and must not advertise writes to the kernel-owned return context. `MachineStackMarker.cpp` already subtracts 128 bytes on x86-64; preserve that behavior and validate that the interrupted RSP is within the retained target's stack before acknowledging suspension. The scanner copies all `PlatformRegisters` bytes, including the FX snapshot, as conservative roots.
* `Threading.h` and the POSIX implementation need a separate request for each retained `Thread`, including a non-reused native TID captured on that thread before publication, a saturating ticket, atomic phase, and a per-request semaphore. The existing `ThreadSuspendLocker` is global, but a collector can suspend multiple targets before resuming them; a single global request or semaphore cannot encode those simultaneous suspended contexts. Target-side access must not acquire `m_mutex`, allocate, or depend on looking up an opaque `pthread_t` in a signal handler. Establish the target's TLS association during thread initialization and retain the `Thread` until its matching RUNNING acknowledgement.
* Install only SIGUSR1 with `SA_SIGINFO`, with the signal blocked in the action mask. Reject configuration that requests another signal or restart semantics. Save and restore `errno` on all normal handler returns. Check the native INFO validity and target TID and the request ticket and phase before publishing the interrupted context. Signal delivery or registration failure must be terminal, not a skip of a potentially live mutator.
* Publish REQUEST then signal. The outer handler publishes context and SUSPENDED before posting its acknowledgement. While suspended, it repeatedly uses the atomic temporary-mask wait; a nested signal with no matching RESUME request must return to the outer wait, not release the context. On RESUME the outer handler clears the context and publishes RUNNING, then performs its final acknowledgement without further request accesses. The coordinator validates the exact phase and ticket and waits with `sem_trywait` plus yield and a ten-second monotonic deadline. Overflow, timeout, target retirement uncertainty, a send failure or a mismatched/late acknowledgement terminates the process. A semaphore post failure is terminal as well.
* Source integration must verify target-thread initialization, retained-reference lifetime and teardown against real WebKit call sites, and use only lock-free atomics from the handler. The existing `m_suspendCount` is coordinator-owned and must not be used as the signal handler's concurrent phase. Tests must exercise multiple suspended targets, spurious and coalesced signals, nested resume, target exit, ticket exhaustion, timeout, errno preservation, original register/FX bytes, and a root in the x86 red zone. Real guest tests are required after the public signal and atomic wait contracts are accepted.

The accompanying `srvros-signal-context.patch` is a review candidate applied only when `browser_jsc_build.py --experimental-signal-context` is selected. Review the lifecycle and handshake as one change. Changing only the register view or signal flags would leave the old global-semaphore suspension protocol unsafe.

The retirement candidate blocks SIGUSR1 before examining the idle phase and pending set, clears the handler's TLS pointer before `didExit` and the TLS-owned dereference, and leaves SIGUSR1 blocked until native exit. A sender racing after the idle/pending check cannot make the handler dereference the retired pointer; its request must fail terminally on send or bounded acknowledgement timeout. The public mask and pending operations used here remain dependent on the staged signal contract.

The RUNNING acknowledgement depends on the successful `sem_post` compare-exchange being the **last access to the request semaphore's storage** in the target's generated code. The handler publishes phase and ticket, restores errno, and calls `sem_post` without a later source-level request access. This is not proven by the source alone: qualify the pinned target `sem_post` and handler assembly with the final SDK flags, including the successful and error paths, before enabling the overlay. The small host protocol model does not exercise atomics, native signals, object lifetime, or target code generation.

The overlay disables `HAVE_STACK_BOUNDS_FOR_NEW_THREAD` only on SrvrOS. The existing child-start handshake then calls `initializeInThread` on the target, initializes the signal state and obtains the real current-thread stack before `allThreads().add`, and acknowledges initialization before the creator completes. This removes the pre-initialization publication window; it still requires target compilation and a concurrent startup/collector guest regression.

The companion `signal-stack-bounds.patch` provides the current-thread stack query directly on SrvrOS. Disabling the early new-thread API also removes its declaration, so the generic POSIX definition/call cannot remain selected. The SrvrOS path checks the actual `pthread_getattr_np`/`pthread_attr_getstack` results and fails terminally on query failure; it does not restore early thread publication.

`wtf_signal_guest.cpp` is a separate target fixture, not a GC root-retention test. Once an experimental-overlay JSC build is available, link it with `python3 ports/srvros/webkit/build_wtf_signal_probe.py --jsc-receipt /absolute/path/to/run/receipt.json`. The adapter requires the experimental flag in that receipt, reuses the existing builder's verified Release profile, and records its own and the adapted builder's hashes after a successful link. Require the `signal_probe_adapter` receipt field when consuming its output. The fixture checks real WTF suspend/resume snapshots and post-resume register/red-zone bytes, two retained suspended targets, a sent extra signal, and repeated worker lifetimes. A sent signal plus yields does not prove that the nested handler ran before resume. The fixture has no supported ticket-overflow/timeout injection or only-root GC test; those remain separate acceptance work.
