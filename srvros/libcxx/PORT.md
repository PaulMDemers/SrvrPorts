# Experimental threaded libc++ slice

Run `python3 ports/srvros/libcxx/build.py` after `make srvros-sysroot` and installing the pinned Zig 0.15.2 toolchain. It compiles the Zig-distributed upstream libc++ sources named in the script with the local config and links `build/browser-runtime/cxxthreads.elf` against the real SrvrOS pthread implementation. The reusable `libcxx-threaded.a` excludes the guest and OS runtime; the guest links it before the freshly rebuilt SDK archive. Each compilation and the link have logs and a hashed receipt under that directory. Upstream LLVM libc++ files carry the Apache-2.0 license with LLVM exception; see the headers in the pinned Zig distribution. No Node probe shims, guest execution, image build, exception unwinder, dynamic loader, or complete C++ standard library are provided by this recipe. The output is a narrow experiment, not a general ABI or WebKit port.

`all` (also the default) checks contended mutex updates, condition-variable timeout and wake, call-once, concurrent local-static construction, guard abort/reacquire, DSO-filtered and recursive global finalization, LIFO thread destructors including registration during drain, and repeated worker creation; success emits `cxxthreads: ok`. `cxxthreads-tlsfirst.elf` is a separate fixture without C++ globals; it registers TLS before a global destructor and checks they run in that order. A main-thread TLS destructor emits `cxxthreads: main tls destructor` during normal exit. `exhaust` holds eight workers and prints `cxxthreads: capacity=8; next construction must abort` before attempting a ninth. In this no-exceptions build, creation failure reports a system error and calls abort; this is deliberately fatal and is not the standard recoverable `std::system_error` behavior. Run this case as a separate guest process. Readiness waits time out after 15 seconds; the VM harness must also impose a whole-process timeout.

Thread and condition-variable operations are upstream libc++ code forwarding to the existing pthread implementation. `future.cpp` is included for actual `thread.cpp` destructor dependencies; this does not establish a supported future API. `fail_fast.cc` supplies explicit terminating behavior for no-exceptions system errors and `std::terminate`; it does not pretend errors succeeded. All consumers must use this same libc++ configuration and cannot mix its thread ABI with the older no-thread Node probe configuration.

The C++ ABI changes in `userspace/lib/src/cxx_runtime.cc` use a pthread key to drain per-thread C++ TLS destructors in LIFO order, including registrations made by a destructor. One shared process atexit callback drains the exiting thread before global C++ destructors on ordinary `exit`/return from main; `_exit`, abort, and forced termination intentionally do not run it. The guard implementation serializes concurrent initializers and wakes waiters on release/abort. This is not a complete C++ ABI: process-global destructor registration is bounded at 128 records and finalization removes entries before invoking them outside the lock; static-ELF DSO filtering is supported, while dynamic unloading is unsupported. Concurrent finalizers may execute distinct callbacks concurrently; global LIFO completion is only claimed for single-caller finalization. Recursive finalization and registration can run outside the lock; recursive initialization and initializer thread death are not recovered, and the process `atexit` registry itself is not a general concurrent teardown facility. ELF TLS has an existing 4096-byte kernel template limit. No behavior has been accepted in a guest solely by a successful build.

`notify_all_at_thread_exit` and promise/future readiness at thread exit are outside the supported slice. The upstream thread proxy initializes its pthread key before entering the user function, while C++ TLS first initialized inside that function gets another key. The current pthread implementation allocates the lowest free key and drains keys in ascending order, so libc++ can publish thread-exit notifications or future readiness before C++ TLS destructors run. Earlier TLS initialization can reverse that order. Supporting these features requires a coordinated pthread lifecycle ordering contract.
